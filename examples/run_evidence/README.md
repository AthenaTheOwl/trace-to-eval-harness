# examples/run_evidence

This directory holds canonical example packets produced from real CDCP
event logs. Each `*.packet.json` validates against
[`schemas/run-evidence.schema.json`](../../schemas/run-evidence.schema.json).

Packets in this directory follow the v2 packet shape
([`DEC-TTE-008`](../../decisions/DEC-TTE-008-run-evidence-packet-preserves-producer-identity.md)):
every packet preserves `producer_run_id` from the producer's Run
record, carries `run_record_ref`/`run_record_hash` and
`event_log_ref`/`event_log_hash` for provenance, and clones the three
replay-equivalence fields (`prompt_snapshot_hash`,
`tool_schemas_snapshot_hash`, `sandbox_image_ref`) plus
`artifact_refs`/`artifact_hashes` from the Run record when present.

## Anchors

- Source-of-truth Run schema: amended in
  [`DEC-CDCP-011`](https://github.com/AthenaTheOwl/athena-site/blob/main/decisions/DEC-CDCP-011-run-records-carry-replay-equivalence-evidence.md)
  on athena-site; carries the six replay-equivalence fields the packets
  exercise.
- Review-boundary packet contract: fixed in
  [`DEC-TTE-007`](../../decisions/DEC-TTE-007-run-evidence-packet-as-review-boundary.md)
  and amended by
  [`DEC-TTE-008`](../../decisions/DEC-TTE-008-run-evidence-packet-preserves-producer-identity.md)
  in this repo. The `evidence from-cdcp-events` CLI reads any CDCP
  event log + its sibling Run record and produces a packet that
  downstream review surfaces can consume without knowing how the
  producer is wired.

## How to regenerate

Every packet in this directory was produced by the same two-step
recipe. The generator now auto-discovers the producer Run record at
`<event-log>/../run-records/<run_id>.json`; pass `--run-record <path>`
to override the lookup for non-standard layouts. The first generation,
against a procurement-negotiation-lab factory ledger, is shown below;
the same shape applies to every other ledger in the portfolio.

```powershell
# From this repo's root.
python -m trace_to_eval evidence from-cdcp-events `
  ../procurement-negotiation-lab/ops/event-ledger/run-16a7bf515611.jsonl `
  --out examples/run_evidence/run-16a7bf515611.packet.json

python -m trace_to_eval evidence validate `
  examples/run_evidence/run-16a7bf515611.packet.json
```

The validate command exits 0 for every packet listed above; each
matches `run-evidence.schema.json` published at
`https://trace-to-eval.dev/schemas/v2/run-evidence.schema.json`.

## Why this directory matters

Without an emitter the schema fields are dead letters. Without a
consumer the packet has no review surface. The packets here are the
handshake, repeated across the portfolio:

- The source-of-truth Run schema lives in athena-site and is shared
  by every producer.
- Five product repos run their own emitter wiring on top of it,
  writing event ledgers in their own languages and pipelines.
- This repo's `evidence from-cdcp-events` CLI reads any of those
  ledgers plus the sibling Run record and writes a packet that any
  review surface can consume.

The bridge is the contract; the packets here are what it produces in
practice — with producer identity, Run-record hashes, and replay-
equivalence hashes preserved so any consumer can trace a packet back
to a specific run.
